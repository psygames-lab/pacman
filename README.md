# Pac-Man · 吃豆人

用 Godot 4.6 制作的街机吃豆人复刻。第一关保留经典迷宫的 240 粒普通豆和 4 粒能量豆。第 2 至 5 关各有独立迷宫和收集任务。过关保留分数和剩余生命，第 6 关从经典迷宫开始下一轮。画面由程序绘制，音效由程序合成。

## 运行

用 Godot 4.6 打开 `project.godot`，按 **F6** 运行已打开的 `game.tscn`，或按 **F5** 启动项目。也可以在仓库根目录运行：

```sh
godot --path .
```

- 游戏窗口默认最大化，迷宫随窗口等比缩放。得分、生命和关卡显示在迷宫上方。
- **按住方向键 / WASD** 移动，松开所有方向键会立即停在当前位置。在走廊中按反方向可立即掉头。按住前进键时，可在接近路口时轻点转向；刚过路口中心也能拐进去。迷宫中部的左右出口互通。
- **空格 / P / Esc** 暂停或继续。每次就位后按方向键或空格开始。
- 每局有三条命。普通豆得 10 分，能量豆得 50 分。一次能量效果中连续吃鬼依次得 200、400、800、1600 分。被吃掉的鬼以眼睛形态回巢，出门后恢复威胁。
- 生命用尽后按 **回车 / 空格** 重新开局。

## 关卡与任务

走过道具即可拾取，集齐时立即发放奖励。吃完豆子并收齐该关道具即可过关。迷宫下方显示收集进度，损失一条命仍保留本关进度。

| 关卡 | 收集任务 | 奖励 |
| --- | --- | --- |
| 02 铜锁宝库 | 2 把铜钥匙 | 打开宝箱，加 500 分 |
| 03 冰晶峡谷 | 3 枚冰晶 | 幽灵冻结 5 秒，碰到普通幽灵仍会掉命 |
| 04 脉冲电网 | 3 节电池 | 12 秒内普通豆和能量豆得分翻倍 |
| 05 星环天文台 | 3 枚星章 | 增加 1 条生命，可带到下一轮 |

## 四鬼如何追击

| 幽灵 | 追击时的目标格 |
| --- | --- |
| 红鬼 Blinky | 玩家当前所在格。 |
| 粉鬼 Pinky | 玩家面前第四格。玩家朝上时，目标同时向上、向左偏移四格。 |
| 青鬼 Inky | 取玩家面前第二格作为中点，把红鬼位置绕中点对称，得到目标格。朝上时中点同时向上、向左偏移两格。 |
| 橙鬼 Clyde | 与玩家的直线距离大于或等于八格时追玩家，小于八格时向左下角撤退。 |

四鬼在路口排除原路返回，再选择距目标最近的下一格。距离相同按上、左、下、右取舍。散开阶段各回自己的角落，散开与追击切换时掉头。能量豆暂停阶段计时，受惊的鬼在路口随机选路。各关使用街机第一关的阶段时序，移动速度和受惊时长随关卡调整。

目标格及路口规则参考 Jamey Pittman 的逆向分析。[The Pac-Man Dossier](https://pacman.holenet.info/)

## 验证

### PsyGodot 行为采集与 EEG 码表

直接按 **F5** 打开被试登记页，输入代号后点击 **开始记录** 或按回车。留空会记为 `anonymous`。登记页显示完整保存路径。默认写入游戏目录下的 `output` 文件夹：编辑器运行时与 `project.godot` 同级，Windows 导出版本与游戏 EXE 同级。被试代号写入每局会话清单的 `participant_label` 字段。选择 **仅试玩** 可跳过采集。也可以在项目目录打开 PowerShell，用下面的命令直接开始记录，把 P001 换成被试代号。

```powershell
& D:\Godot\Godot_v4.6.2-stable_win64_console.exe --path . -- --psygodot --participant=P001
```

研究模式自动采集每个物理帧的状态（默认 60 Hz），旧命令中的 `--psygodot-frames` 可省略。加 `--psygodot-markers` 记录模拟标记。用 `"--output-dir=D:\study data\pacman"` 指定其他目录，或传 `--output-dir=pilot` 写入游戏目录下的 `pilot`。启动时控制台会打印绝对路径。每次重新开局创建新的会话。用游戏窗口的关闭按钮正常退出，让后台写入器收尾；实验后核对 manifest 中的 `recording.complete` 和丢弃计数。

每局输出 JSONL 原始事件及 JSON 会话清单。行为事件涵盖就位、开始、方向键按下与松开、失焦、暂停与恢复、吃豆、能量豆、吃鬼、掉命、任务拾取、奖励、过关和游戏结束。每条带单调微秒时间戳，游戏事件另带关卡、玩家格坐标、分数和生命。轨迹样本中幽灵按红、粉、青、橙排列。每项为 `[x, y, state, scared, dx, dy]`，旧版仅有前四项。状态编号依次为 0 鬼屋、1 出门、2 游走、3 回巢、4 入门。

### 回放、标注与特征导出

从登记页进入 **回放与标注**，选择 `*_raw_events.jsonl`。配对的 `*_session_manifest.json` 需在同一目录。界面按游戏会话时钟播放，支持拖动时间轴、逐样本步进、跳到下一条行为事件以及 0.25、0.5、1、2 倍速。未启用轨迹的历史记录只显示最近一次事件中的玩家格位置；有轨迹时显示最近一次已记录样本。回放是观察到的游戏状态，不包含屏幕呈现或音频的物理起始时间。

输入标注者代号和标签，点 **保存标注** 创建点标注；也可先 **设区间起点**，移动到终点，再保存。每条标注独立存入同目录的 `*_annotations/`，包含会话 ID、起止原始事件 ID 和起止微秒时间。重新打开后可从标注列表跳回起点。多人可对同一段行为独立编码。

**导出特征** 在同目录生成 `*_features.tsv`，每行与一个原始事件 ID 对应，可按会话、事件 ID 或时间区间与标注关联。包括按键、玩家和四鬼坐标、实际朝向变化、相邻样本时间差和位移。坐标和距离单位为格，计时单位见列名。最近威胁距离取正在游走且未受惊的鬼到玩家的最小直线距离，两者同处横向隧道行时考虑左右贯通；冻结且仍可造成碰撞的鬼也计入。该指标不考虑墙体遮挡和绕墙路径。位移仅在同一次生命、连续物理 tick、两帧均可操作时计算。缺失值留空，`heading_changed` 表示该物理步实际改变朝向（含掉头）。同名特征表可从原始数据重新生成。

| 软件事件 | 研究码 |
| --- | --- |
| 本条生命开始可操作、暂停、恢复 | 10、11、12 |
| 吃能量豆、吃鬼、掉命 | 20、21、22 |
| 拾取任务道具、发放任务奖励 | 30、31 |
| 过关、游戏结束 | 40、41 |

模拟标记行带有 `driver=mock`、研究码和指向原始事件的 `linked_event_id`。这些时间描述游戏逻辑观察时刻。当前集成没有 LSL 或 TTL 输出。接 EEG 时需配置匹配的发送端，并在 EEG 记录端验证收码、时钟对齐和延迟；视觉刺激的实际亮起时刻可用光电二极管核对。

事件和码表的维护入口是 `telemetry/event_catalog.json`。运行时及离线工具来源为 [PsyGodot c91ead6](https://github.com/psygames-lab/psygodot/tree/c91ead6f67b397e5f7c5fdb098f446acbed68ef5)。以下示例假定两个仓库相邻。HED 转换需先在 Python 环境中安装 PsyGodot 的 `analysis/requirements.txt`。将文件变量指向同一局的文件，导出目录需为新路径。

```powershell
python ../psygodot/analysis/validate_events.py $raw --manifest $manifest
python ../psygodot/analysis/convert_hed.py $raw --manifest $manifest --mapping analysis/hed/mapping.json --output $newOutputDir
python ../psygodot/analysis/generate_catalog.py telemetry/event_catalog.json --markers telemetry/marker_config.json --hed-dir analysis/hed --check
```

导出的 `events.tsv` 以游戏会话起点计时，配套 `events.json` 包含 HED 注释。与 EEG 合并前需换算到该次 EEG 记录的时间轴。
